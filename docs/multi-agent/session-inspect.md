# 他セッションのやり取りを見る（#1477）

**いつ読むか**: 走っている（または畳んだ）別の実装セッションが何をしているか・何を話したかを
確認したいとき。見た内容をもとに次の手を打ちたいとき。

索引: [Issueごとの複数Claude Codeエージェント運用 設計](../multi-agent-workflow.md)

## 結論

**他セッションのやり取りは全量が読める。** 画面をスクロールで流れて消えた分も残っている。
走行中のセッションでも、その時点までの内容をそのまま読める（#1477で実地に確認した）。

読んだ内容をもとに**別の場所で**検証・実装することもできる。できないのは「読んだ結果から
そのセッションへ指示を送る」ことだけで、これは後述のとおり意図的に塞いである。

## 見る経路は3つある

| 経路 | 見えるもの | 向き・限界 |
|---|---|---|
| `tmux attach -t <名前>` / `tmux capture-pane` | 画面の見た目そのもの。承認プロンプトや選択フォームが出ていることも分かる | 人が目で見る用。`history-limit`（既定2000行）より前は消えている |
| 転記（`~/.claude/projects/<スラッグ>/<sessionId>.jsonl`） | **やり取りの全量。** 発言・ツールの呼び出しと結果・作業ディレクトリ・ブランチ | 1セッションで1.5MBを超える。素で読むとトークンが重い |
| Remote Control（`https://claude.ai/code/<bridgeSessionId>`） | 会話を見て**その場で答えられる** | ブラウザ用。URLはissue-deckのDB（`DispatchSession.remoteControlUrl`）にある。詳細は [session-notify.md](session-notify.md) |

転記が一番情報が多く、かつ一番扱いづらい。そこを畳むのが `scripts/inspect-session.sh`。

## `scripts/inspect-session.sh`

```bash
scripts/inspect-session.sh                      # 生きているセッションの一覧
scripts/inspect-session.sh 1473                 # Issue番号で指定
scripts/inspect-session.sh dayspan-issue-222    # tmuxセッション名で指定（別リポジトリも同じ）
scripts/inspect-session.sh 1473 -n 30           # 直近30件（既定10）
scripts/inspect-session.sh 1473 --with-tools    # ツールの呼び出し・結果も混ぜる
scripts/inspect-session.sh 1473 --screen        # 画面（capture-pane）の末尾も出す
scripts/inspect-session.sh 1473 --raw           # 転記ファイルのパスだけ（他コマンドへ渡す用）
```

出るのは、セッションの生死・作業ディレクトリ・ブランチ・転記の場所と大きさ・最終更新時刻に続いて、
直近のやり取りとツール使用の内訳。

### 既定で「文章だけ」を出す理由

転記の行数の大半はツールの呼び出しと結果で、そのまま並べると**何をしているかを表す文章が流れて
見えなくなる**。既定ではテキストを持つ発言だけを出し、ツールの流れは末尾の内訳（`Bash x126 /
Edit x35 / ...`）で足りるものとして扱う。個々のツール呼び出しを追いたいときだけ `--with-tools`。

### 解決の順序

判断は挟まず、決定的に引く。

1. 引数が数字なら `tmux ls` から `*-issue-<番号>` を探す。**複数当たったら選ばずに落とす**
   （リポジトリ違いで同じ番号があり得る。黙って片方を掴むと別のセッションの中身を見せてしまう）
2. セッション名 → 作業ディレクトリ。生きていれば `#{pane_current_path}`、取れなければ worktree の
   規約（`<repo>-issue-<n>` → `~/apps/<repo>-worktrees/issue-<n>`）で補う
3. 作業ディレクトリ → 転記の置き場。**非英数字を `-` へ置換したもの**が `~/.claude/projects/`
   配下のディレクトリ名。外れたときだけ、各ディレクトリの `cwd` フィールドと突き合わせる総当たりへ
   落ちる
4. その中で mtime が一番新しい `.jsonl`（セッションを再開すると増える）

### Claude Codeの内部仕様に依存している

転記の置き場所・ディレクトリ名の作り方・JSONLの `type` の値は、いずれも公開仕様ではない。
**壊れたら黙って諦める側へ倒し**、読めないことを人向けの文言で伝えて終わる。
[session-notify.md](session-notify.md) が Remote Control のURL解決（`~/.claude/sessions/<pid>.json`）に
ついて置いている断りと同じ扱いで、ここに依存した判定を他の仕組みへ広げないこと。

同じ理由で、**転記を読むのはこのスクリプトと `scripts/session-notify.sh` だけ**に留める。
pollerなどの常駐側は転記を読まない（[gates.md](gates.md)「計器」）。

## 見た内容をどう扱うか

### 出力は端末に留める

転記には実装中のコード・環境変数・トークンが映りうる。**Issueコメント・PR本文・DBへ貼らない。**
`src/lib/dispatch/session-escalation.ts` が「画面（`capture-pane`）の内容は載せない」としているのと
同じ理由で、そちらはサーバーへ送る経路そのものを持たないのに対し、こちらは人の端末に出すだけで
受けている。仕組みでは防げないため、貼らないことを規約として持つ。

### そのセッションへ指示を送らない

**読んだ結果からエージェントが文字列を組み立てて`send-keys`するのは禁止**
（`CLAUDE.md`「監視・計画レビューを行う実行体の禁止事項」）。選択フォームの表示中に本文＋Enterを
送り、1問目が既定の選択肢で勝手に回答済みになった事故が根拠。例外は人が押した1回の操作だけで、
画面の「停止」（固定の`C-c`）と「追加指示を送る」（人が書いた1行を3段階プロトコルで送る。#1012）に
限られる。

**このスクリプトは読むだけで、送る経路を持たない。** 見た結果として何かを実装したくなったら、
そのセッションへ流し込むのではなく**新規Issueとして起票して通常のフローへ戻す**
（[branching.md](branching.md)「セッション中に作った新しいIssueは、そのセッションで実施しない」）。

### 常駐して見張る役は増やさない

このスクリプトは人が叩いたときに1回読んで出すだけで、常駐しない。**定期的に走らせて内容を分類し、
状態を推定する使い方はしないこと。** 画面の文字列から状態を推定する方式は実地で誤判定した実績が
あり（#1219・#1223）、入力待ち・完了・停滞はフックが、異常終了・セッション消失はpollerが、
それぞれ画面の内容を読まずに担当している（[gates.md](gates.md)「計器の担当範囲は『フックが飛ぶか』で
切る」）。監督のための役を立てない判断（#1200）も変わらない。

## エージェントに使わせるとき

読むこと自体は許されるが、転記は長い。既定（10件・1行180文字で切る）のまま使い、必要なときだけ
`-n` を増やす。`--raw` で転記ファイルのパスだけを取り、`jq` で必要な断片に絞る使い方もできる。

```bash
# 例: 相手のセッションが最後にどのファイルを編集したか
jq -r 'select(.type=="assistant") | (.message.content // []) | if type=="array" then .[] else empty end
       | select(.type=="tool_use" and (.name == "Edit" or .name == "Write")) | .input.file_path' \
   "$(scripts/inspect-session.sh 1473 --raw)" | tail -5
```
