# IssueのActions実装を廃止する（#4680）

未使用のIssue実装経路を削除し、計画・実装・計画レビューはホスト実行へ一本化する。

## 削除したもの

- `claude-issue-dispatch.yml` と `reusable-issue-dispatch.yml`
- 専用の計画・実装・分割・質問・計画レビュープロンプト、専用の参照文書
- 実行先のActions選択肢、ホスト不在時のActionsへの切り替え
- Project Status変更からActionsを起こすコメント投稿
- 新規アプリに旧Issue callerを生成する処理

ホスト不在時は実装プロンプトをコピーできる。実装対応の判定とProjectへの補完登録はホストの対応リポジトリを使う。質問ボタンは質問コメントを保存した後、既存の質問ジョブ、または対象Issueの生存セッションへの読み取り専用の指示へ送る。ホストが無ければ理由を表示する。

## 残すもの

CI、デプロイ、リリース、ラベル・進捗同期、PRレビュー、CI修復・コンフリクト解消・レビュー修正は維持する。これらはIssueの実装経路とは別の責務である。ホスト実行側の計画承認・計画レビューの回数制限も変更しない。

過去のコメント・レビュー結果・実行履歴は削除しない。自由文のPR修正依頼も旧Issue実装への投稿を停止し、Issue詳細のホストセッションを案内する。専用のPR修復ワークフローには影響しない。

DBの旧workflow有無のキャッシュと旧タグからのコメント転送APIは互換用に残すが、実装を開始できるかの判断には使わない。

## 既存の配布先

既存の `workflows/vN` タグは変更しない。他リポジトリの旧callerを削除する場合は、そのリポジトリのIssueとPRで扱う。このPRは他リポジトリのファイルを変更しない。

旧 `reusable-issue-dispatch.yml` を呼ぶファイルはタグ更新の検出・配布から除外する。新タグで存在しないファイルを参照させないためである。既に作成済みの配布PRは、マージ前に旧callerの参照を上げていないか確認する。

残す修復callerの配布は、旧Issue caller、CI修復、コンフリクト修復、PR修復、レビュー修正の順で設定の引き継ぎ元を探す。候補が一つも無いリポジトリでは初回の修復callerを手動設定する。UIと配布スクリプトで候補の順序を揃える。

## 確認

- 実行先にActionsが出ず、対応ホストまたはコピーを選べる。
- ホスト情報や `11.local` が無くても、Actionsの起動待ちを表示しない。
- 質問保存前には起動せず、保存後の起動拒否を成功として隠さない。
- 新規アプリの生成物に旧callerが無く、初期化Issueにホスト準備の前提がある。
- タグ配布で旧callerが変更されず、残す修復callerの配布を継続できる。

本番でのホスト起動と新規リポジトリ作成の確認は、マージ・デプロイ後に行う。
