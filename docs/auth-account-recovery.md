# 認証IDが変わった場合のログイン復旧

IssueDeckのUser.idは設定・履歴・連携の所有者を表す。Supabaseのユーザーが再作成されても、User行を削除して作り直さない。

ログインの許可をStatusHubで確認した後、今回のOAuthのprovider_tokenをGitHubのGET /userへ照会し、不変のGitHub IDを取得する。このIDをキーに既存UserのsupabaseUserIdを更新する。利用者が変更可能なuser_metadata、メール、GitHubログイン名を本人確認・アカウント統合の根拠にしない。既存のsupabaseUserIdが別のGitHub IDに属する場合は更新を拒否する。

認証拒否や設定取得失敗で共有Supabaseの認証ユーザーを削除しない。signOutはlocalスコープに限定する。コールバックの保存・本人確認に失敗した場合はログイン画面で再試行を案内する。

## 適用後の確認

- ログイン画面から新しくGitHubログインを開始する（使用済みのコールバックURLは再利用しない）。
- ダッシュボードへ移動し、以前の設定・履歴・連携が表示されることを確認する。
- 未許可アカウントを拒否し、認証ユーザーが削除されないことを確認する。
- DB障害やGitHub本人確認失敗では、白画面にならず再ログインを案内する。

DBスキーマ変更・データ削除・手動の全件移行は不要。再ログインした本人の紐付けだけが更新される。本番の復旧完了は実ログインと既存データの確認後に判定する。旧版へ戻すと、認証拒否時の削除と認証ID変更時の重複エラーが再発し得る。
