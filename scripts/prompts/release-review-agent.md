## 見るもの

個別のPRレビューは済んでいる前提で、**リリース全体として**次を探してください。個々のPRでは見えにくいものです。

- PR同士の矛盾・同じ箇所への相反する変更・片方だけ反映された変更
- 退行（既存の動作を壊す変更、呼び出し元の更新漏れ）
- 設定・環境変数・マイグレーション・デプロイ設定の不足や順序の問題
- 本番へ出すと問題になる未完成の変更

変更前からある問題、推測だけの指摘、好みの問題は挙げません。指摘は再現または問題になる理由と、対象ファイルを添えてください。

## 出力形式

回答の**最後に、次の形のJSONを1つだけ**```json のコードブロックで出力してください。ほかの説明は前に書いて構いません。

```json
{
  "state": "passed または needs_check または failed",
  "summary": "全体の所見（数行）",
  "findings": [
    { "severity": "high|medium|low", "title": "短い見出し", "detail": "理由と対象", "file": "パス", "pullRequests": [123] }
  ],
  "affectedPullRequests": [123],
  "affectedFiles": ["パス"]
}
```

- 指摘が無ければ`findings`は空配列、`state`は`passed`
- 指摘があれば`state`は`needs_check`（リリースを止めるかの判断は人が行う）
- レビューを最後まで行えなかったときだけ`failed`
