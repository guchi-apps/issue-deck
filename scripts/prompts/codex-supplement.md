## Codex CLIで動いている場合の読み替え

**このセッションはClaude CodeではなくCodex CLI（`codex`）で動いています。** ここまでの指示は
Claude Codeを前提に書かれているため、次の点を読み替えてください。**矛盾する場合はこの節が
優先です。** それ以外（責務・禁止事項・Issueに残す記録・PR本文の書式）は同じです。

### 最初に読むもの

- **`CLAUDE.md`を自分で読んでください。** Codexが自動で読むのは`AGENTS.md`で、このリポジトリの
  規約は`CLAUDE.md`と`docs/`にあります。読まないままだとブランチ運用・ラベル運用・出力言語の
  規約を知らずに作業することになります

### 無い機能と、その代わりにやること

- **Plan mode・`ExitPlanMode`はありません。** `21.plan-required`が付いている場合は、計画を
  `gh issue comment <Issue番号>`で投稿し（末尾に`<!-- issue-deck-agent:planner -->`）、
  `gh issue edit <Issue番号> --add-label "00.check-user" --add-label "01.check-plan"`を
  **自分で**付けたうえで、端末でユーザーの承認を待ってください。**フックが計画を代わりに投稿する
  ことはありません。** 冒頭に`<!-- plan-base: <SHA> -->`（`git rev-parse origin/develop`）を
  残すこと、書式（`## 要約`から始めて30〜40行）は変わりません
- **`AskUserQuestion`はありません。** 確認が必要なときは端末で質問し、同じ内容をIssueコメントにも
  投稿して`00.check-user`＋`01.check-input`を**自分で**付けてください。**答えが出たら自分で
  外します**（フックが外してくれることはありません）
- **`Read`・`Grep`・`Glob`はありません。** ファイルを読む・探すのはシェル（`sed -n`・`rg`・`ls`）で
  行ってください。ただし「往復を減らす」という趣旨は変わりません。依存の無い調査は1つのコマンドに
  まとめ、同じ場所を何度も読み直さないでください
- **承認プロンプトは出ません。** `--ask-for-approval never`で起動しており、コマンドは確認なしに
  実行されます。**危険な操作の歯止めは自分の判断とサンドボックスだけ**だと思ってください
- **画面（issue-deck）側の連携が一部効きません。** 入力待ちの通知・計画の承認パネル・Remote
  Control・「追加指示を送る」は出ません。**セッションの開始／終了・プレビューURL・応答終了
  （停止）の報告と「まだ開始していません」の検知は行われます**（`SessionStart`・`Stop`の
  フックを繋いであります。#2509）。**進捗と判断をIssueコメントに残すことが、Claude Codeで
  動くとき以上に重要です。** 端末だけで完結させると、外から見ると何も起きていないように見えます
- **`00.check-user`は誰も自動では付けません／外しません。** Claude Code側はフックが付け外しを
  しますが、この経路には承認プロンプトも質問フォームも無いため、上の2つの手順どおり
  **自分で付け、答えが出たら自分で外して**ください
- **前回の会話は引き継がれません。** セッションを起こし直した場合は、`gh issue view <Issue番号>
  --comments`とこの指示ファイルを読み直してから続きに入ってください

### 書き込みの範囲

- 書き込みはサンドボックスによって**このworktreeの中**と**gitの管理領域（本体の`.git`）**に
  閉じています。本体チェックアウト・他Issueのworktree・共有知識リポジトリ（`~/apps/_docs`）の
  ファイルへは書き込めませんし、書き込もうとしないでください（もともと禁止事項です）
- **`git add`・`git commit`・`git push`はそのまま通ります。** worktreeの`.git`は本体側を指すだけの
  ファイルで、インデックスもオブジェクトも本体の`.git`にあるため、そこだけ書けるようにしてあります。
  `index.lock: Read-only file system`のようなエラーが出たら、迂回せずIssueコメントで報告してください
- ネットワークは開けてあります。`gh`・`git push`・`pnpm install`はそのまま使えます
