## Codex CLIで動いている場合の読み替え

**このセッションはClaude CodeではなくCodex CLI（`codex`）で動いています。** ここまでの指示は
Claude Codeを前提に書かれているため、次の点を読み替えてください。**矛盾する場合はこの節が
優先です。** 特に、本文や古い起動スクリプトに残ったPlan mode／`ExitPlanMode`／
「計画を`gh issue comment`で手動投稿する」という指示は実行しないでください。
それ以外（責務・禁止事項・Issueに残す記録・PR本文の書式）は同じです。

### 最初に読むもの

- **`CLAUDE.md`を自分で読んでください。** Codexが自動で読むのは`AGENTS.md`で、このリポジトリの
  規約は`CLAUDE.md`と`docs/`にあります。読まないままだとブランチ運用・ラベル運用・出力言語の
  規約を知らずに作業することになります

### 無い機能と、その代わりにやること

- **Plan mode・`ExitPlanMode`はありません。** `21.plan-required`が付いている場合は、計画を一時的な
  Markdownファイルへ書いたあと、**必ず**`scripts/submit-plan.sh <計画ファイル>`を実行してください。
  このコマンドが計画コメント・待機ラベル・画面の承認パネルを作り、同じCodexプロセスが判断を
  待ちます。**`gh issue comment`で計画を手動投稿してはいけません。** 手動投稿では返事待ちが
  作られないため、画面から承認してもsubPCのセッションへ届きません。終了コード`0`なら実装へ進み、
  `2`なら修正を反映して同じコマンドで再送し、`3`なら実装へ進まず端末で判断を確認してください。
  書式（`## 要約`から始めて30〜40行）は変わりません
- **`AskUserQuestion`はありません。** 確認が必要なときは、質問を同じスキーマのJSON配列
  （`question`・`header`・2〜4件の`options`・`multiSelect`）として一時ファイルへ書き、
  `scripts/submit-question.sh <質問JSONファイル>`を実行してください。issue-deckに選択肢と
  「その他」の入力欄が出て、回答時は終了コード`0`と標準出力のanswers JSONが返ります。
  終了コード`2`は端末での回答へ切り替え、`3`は期限切れ・通信失敗です。いずれも回答済みと
  みなさず、端末でユーザーへ確認してください
- **`Read`・`Grep`・`Glob`はありません。** ファイルを読む・探すのはシェル（`sed -n`・`rg`・`ls`）で
  行ってください。ただし「往復を減らす」という趣旨は変わりません。依存の無い調査は1つのコマンドに
  まとめ、同じ場所を何度も読み直さないでください
- **承認プロンプトは出ません。** `--ask-for-approval never`で起動しており、コマンドは確認なしに
  実行されます。**危険な操作の歯止めは自分の判断とサンドボックスだけ**だと思ってください
- **画面（issue-deck）側の連携が一部効きません。** 自動の入力待ち通知は出ませんが、計画と質問は
  上の専用コマンドで画面から判断できます。**「追加指示を送る」と、セッションの開始／終了・プレビューURL・応答終了
  （停止）の報告と「まだ開始していません」の検知は行われます**（`SessionStart`・`Stop`の
  フックを繋いであります。#2509）。**進捗と判断をIssueコメントに残すことが、Claude Codeで
  動くとき以上に重要です。** 端末だけで完結させると、外から見ると何も起きていないように見えます
- **専用コマンドを通さない入力待ちの`00.check-user`は誰も自動では付けません／外しません。**
  計画と質問は送信コマンドと画面が扱います。見覚えのないプロンプトなど、質問コマンドで表せない
  停止だけはIssueコメントと`00.check-user`＋理由ラベルを自分で管理してください
- **同じworktreeでセッションを起こし直すと、前回の会話を引き継ぎます。** ランチャーが
  `SessionStart`フックで残したUUIDを指定して`codex resume`するため、`--last`のように別Issueの
  セッションを拾いません。再開時も、前回以降の変更を取り込むため`gh issue view <Issue番号>
  --comments`とこの指示ファイルを読み直してから続きに入ってください

### 書き込みの範囲

- 書き込みはサンドボックスによって**このworktreeの中**と**gitの管理領域（本体の`.git`）**に
  閉じています。本体チェックアウト・他Issueのworktree・共有知識リポジトリ（`~/apps/_docs`）の
  ファイルへは書き込めませんし、書き込もうとしないでください（もともと禁止事項です）
- **`git add`・`git commit`・`git push`はそのまま通ります。** worktreeの`.git`は本体側を指すだけの
  ファイルで、インデックスもオブジェクトも本体の`.git`にあるため、そこだけ書けるようにしてあります。
  `index.lock: Read-only file system`のようなエラーが出たら、迂回せずIssueコメントで報告してください
- ネットワークは開けてあります。`gh`・`git push`・`pnpm install`はそのまま使えます
